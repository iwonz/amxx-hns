# Design

## Context

См. `proposal.md` — Why. До изменения устаревшее отображаемое имя независимо дублировалось в Pawn metadata, README, release script, GitHub Actions и контексте OpenSpec. Кроме того, GitHub-репозиторий и локальный `origin` использовали старый slug `iwonz/amxx-hns`, а README ссылался на его Releases. Переименование затрагивает несколько поверхностей и внешнее состояние GitHub, но не меняет runtime-логику и формат поставки.

## Goals / Non-Goals

**Goals:**

- синхронно заменить отображаемое имя во всех активных источниках;
- перенести canonical GitHub repository path на `iwonz/amxx-hns-ultimate` и обновить управляемые ссылки и текущий `origin`;
- защитить точное написание регрессионным тестом;
- сохранить установочную и конфигурационную совместимость.

**Non-Goals:**

- вводить общую генерируемую константу для Pawn, Python, Markdown и YAML;
- переименовывать локальный каталог checkout, исходники, бинарник, конфигурацию, словарь, Cvar или каталоги ресурсов;
- переписывать исторические упоминания в архивированных OpenSpec changes и уже опубликованных релизах.

## Decisions

### Обновить каждую активную поверхность явно

Строка меняется непосредственно в пяти текущих источниках: `PLUGIN` в Pawn, H1 README, описании `argparse`, `gh release create --title` и project context OpenSpec. Это сохраняет простую структуру проекта и не вводит генерацию исходников ради одной строки. Альтернатива — единый metadata-файл с подстановкой во все форматы — отклонена как несоразмерное усложнение для небольшого Pawn-проекта.

### Считать технические HNS-имена стабильными идентификаторами

Переименование игровых и поставляемых идентификаторов ограничивается человекочитаемым названием; отдельно меняется только GitHub repository slug. `hns.amxx`, `hns.cfg`, `hns.txt`, `hns_` Cvar, каталоги звуков и имена release assets не меняются, поэтому обновление не требует миграции серверной конфигурации. Альтернатива — полное переименование файлов и префиксов — нарушила бы существующие установки и ссылки без пользы для отображаемого бренда.

### Переименовать GitHub-репозиторий после проверки предусловий

Перед внешним изменением нужно проверить аутентификацию `gh`, доступ на администрирование `iwonz/amxx-hns` и отсутствие занятого `iwonz/amxx-hns-ultimate`. После этого репозиторий переименовывается командой `gh repo rename amxx-hns-ultimate --repo iwonz/amxx-hns --yes`, новый URL проверяется через GitHub, а локальный `origin` переключается на `https://github.com/iwonz/amxx-hns-ultimate.git`. Такой порядок не оставляет checkout настроенным на несуществующий target. Альтернатива — полагаться на GitHub redirect со старого URL — отклонена: canonical ссылки и remote должны быть явными.

Локальный каталог `/Users/i.zimin/Desktop/amxx-hns` не переименовывается: имя каталога не влияет на repository identity, а его перенос вышел бы за пределы рабочего root и мог бы нарушить пользовательские инструменты.

### Проверять имя на исходных поверхностях

Статический regression test проверит точную новую строку во всех пяти активных местах, новый GitHub Releases URL в README и отсутствие старых вариантов на управляемых поверхностях. Это выявляет частичное переименование до релиза. Архив OpenSpec исключается из отрицательной проверки, поскольку он намеренно сохраняет историческое состояние.

### Runtime и lifecycle не затрагиваются

Изменение не добавляет и не меняет AMXX events, messages, Ham hooks, Fakemeta forwards, task IDs, precache, callbacks или cleanup paths. Нет работы на игрока, кадр, сообщение или entity think, поэтому производительность не меняется. `hns.cfg` и `hns.txt` не редактируются: конфигурационная совместимость и RU/EN localization остаются прежними. Единственный видимый эффект — новое имя в metadata и материалах выпуска; при пропущенном источнике тест должен завершиться ошибкой.

## Risks / Trade-offs

- [Риск] Новая поверхность в будущем снова использует старое или иное написание → regression test хранит список текущих источников, а OpenSpec requirement задаёт каноническую строку для новых поверхностей.
- [Риск] Пользователь воспринимает `hns` в именах файлов как незавершённое переименование → README и спецификация явно отделяют стабильные технические идентификаторы от отображаемого названия.
- [Риск] Новый GitHub slug уже занят или текущая учётная запись не имеет административного доступа → выполнить read-only preflight и не менять локальные ссылки или `origin`, если предусловия не выполнены.
- [Риск] Старые внешние ссылки и существующие clones продолжают использовать прежний URL → сохранить предоставляемый GitHub redirect как переходную совместимость, но обновить все управляемые ссылки и текущий checkout на canonical URL.

## Migration Plan

Сначала проходят GitHub preflight-проверки. Затем обновляются проверяемые project sources, GitHub-репозиторий переименовывается командой `gh repo rename amxx-hns-ultimate --repo iwonz/amxx-hns --yes`, а `origin` переключается командой `git remote set-url origin https://github.com/iwonz/amxx-hns-ultimate.git`. После проверки fetch/push URL новая сборка автоматически зарегистрирует новое имя, а новые GitHub Releases получат новый заголовок и новый repository path.

Для установки поверх старой версии достаточно заменить `hns.amxx`; переименование или очистка серверной конфигурации не требуются. Откат внешнего шага выполняется обратным переименованием репозитория в `amxx-hns` и восстановлением прежнего `origin`; затем возвращаются управляемые ссылки, пять строк названия и соответствующие тесты. Серверные данные при этом не затрагиваются.
