# Release Versioning Specification

## Purpose

Спецификация обеспечивает однозначную связь версии внутри AMXX-плагина с Git-тегом, проверенной сборкой, устанавливаемым архивом и опубликованным GitHub Release.

## Requirements

### Requirement: Единый источник SemVer

Проект SHALL хранить версию плагина в одном Pawn-совместимом источнике в формате SemVer 2.0.0 без префикса `v`; остальные представления версии SHALL получать значение из него или проверяться на точное совпадение.

#### Scenario: Стабильная версия

- **WHEN** исходник содержит версию `1.2.3`
- **THEN** она принимается как корректная стабильная SemVer-версия

#### Scenario: Предварительная версия и build metadata

- **WHEN** исходник содержит версию `2.0.0-rc.1+build.7`
- **THEN** она принимается как корректная полная SemVer-версия

#### Scenario: Некорректная версия

- **WHEN** версия пропускает компонент, содержит ведущий ноль в числовом компоненте или иначе нарушает SemVer 2.0.0
- **THEN** проверка завершается ошибкой до компиляции и публикации

### Requirement: Версия загруженного плагина

Скомпилированный `hns.amxx` SHALL регистрировать точную версию из единого источника через стандартные метаданные AMX Mod X.

#### Scenario: Администратор проверяет плагин

- **WHEN** сервер загрузил выпущенный `hns.amxx` и администратор выполняет `amxx plugins`
- **THEN** отображаемая версия совпадает с версией соответствующего релиза без префикса `v`

### Requirement: Контракт релизного тега

Релизный Git-тег SHALL иметь вид `v<SemVer>` и SHALL точно совпадать с версией единого источника после удаления только начального символа `v`.

#### Scenario: Совпадающий тег

- **WHEN** версия исходника равна `1.4.0` и workflow запущен тегом `v1.4.0`
- **THEN** проверка тега проходит

#### Scenario: Тег не совпадает с исходником

- **WHEN** версия исходника равна `1.4.0`, а workflow запущен тегом `v1.4.1`
- **THEN** workflow завершается ошибкой до создания GitHub Release

#### Scenario: Невалидный релизный тег

- **WHEN** тег с релизным префиксом не является точным `v<SemVer>`
- **THEN** workflow завершается ошибкой до создания GitHub Release

### Requirement: Проверенная релизная сборка

Релизный workflow SHALL до публикации выполнить regression tests, strict OpenSpec validation и компиляцию официальным закреплённым AMX Mod X 1.10.0.5487 с проверкой целостности загруженного toolchain.

#### Scenario: Все проверки успешны

- **WHEN** тег совпадает с версией, тесты и OpenSpec validation проходят, а `amxxpc` компилирует исходник без ошибок
- **THEN** workflow получает релизный `hns.amxx` и продолжает упаковку

#### Scenario: Проверка или сборка не прошла

- **WHEN** любая обязательная проверка, проверка целостности toolchain или компиляция завершается ошибкой
- **THEN** GitHub Release не создаётся

### Requirement: Устанавливаемый релизный архив

Каждый релиз SHALL содержать архив `hns-v<SemVer>.zip` с готовой структурой относительно каталога `cstrike`: бинарником, поставляемой конфигурацией, словарём и всеми звуками проекта.

#### Scenario: Архив распакован в cstrike

- **WHEN** администратор распаковывает `hns-v<SemVer>.zip` в каталог `cstrike`
- **THEN** появляются `addons/amxmodx/plugins/hns.amxx`, `addons/amxmodx/configs/hns.cfg`, `addons/amxmodx/data/lang/hns.txt` и каталог `sound/hns`

#### Scenario: Архив собран не полностью

- **WHEN** отсутствует обязательный deployable-файл или бинарник не был создан текущим workflow
- **THEN** упаковка завершается ошибкой и GitHub Release не публикуется

### Requirement: Артефакты GitHub Release

GitHub Release SHALL быть связан с проверенным тегом и содержать устанавливаемый архив, отдельный `hns.amxx` и `SHA256SUMS`, покрывающий оба загружаемых файла.

#### Scenario: Публикуется стабильный релиз

- **WHEN** успешно обработан стабильный тег `v1.5.0`
- **THEN** создаётся обычный GitHub Release с тем же тегом, заголовком с версией и автоматически сформированными release notes

#### Scenario: Публикуется prerelease

- **WHEN** успешно обработан тег с prerelease-компонентом, например `v2.0.0-beta.1`
- **THEN** GitHub Release имеет тот же тег и помечается как prerelease

#### Scenario: Release tag отсутствует на GitHub

- **WHEN** команда публикации не может подтвердить существование проверенного тега в удалённом репозитории
- **THEN** новый тег или GitHub Release автоматически не создаётся

### Requirement: Управляемое повышение версии

Документация SHALL предписывать обновлять единый источник версии отдельным изменением и выбирать MAJOR, MINOR или PATCH по правилам SemVer до создания и отправки релизного тега.

#### Scenario: Выпуск новой версии

- **WHEN** сопровождающий готовит релиз
- **THEN** он сначала фиксирует новую версию в исходнике и проходит проверки, затем создаёт и отправляет совпадающий тег `v<SemVer>`

#### Scenario: Обычный push без релизного тега

- **WHEN** commit отправлен в ветку без нового релизного тега
- **THEN** GitHub Release автоматически не создаётся
